## Documentation

Read and follow the documents relevant to the task before making changes:

- `docs/PROJECT.md` — functionality, routes, content policy, and project constraints.
- `docs/DESIGN.md` — layout, typography, palettes, and visual states.
- `docs/guidelines/ARCHITECTURE.md` — stack, rendering, components, and content organization.
- `docs/guidelines/STYLING.md` — SCSS Modules, BEM, and Sass nesting rules.
- `docs/guidelines/TESTING.md` — applicable checks, UI verification, and reporting.

## Work process

1. Inspect the affected source files and relevant documentation.
2. Keep changes within the task; preserve existing content, design, and architecture unless explicitly requested otherwise.
3. Report conflicting requirements or important ambiguities before making dependent changes.
4. Implement the smallest coherent change; avoid unrelated refactoring.
5. Run the applicable checks and inspect rendered UI when appropriate and available.
6. Report the changes, checks actually performed, and unresolved issues. Never claim verification that was not performed.
